# Stress run — 2026-07-30

A large parallel run of the benchmark suite against the v0.3.0 craft toolset,
used to shake out weaknesses in the tools rather than to score models rigorously.

## What's here

19 of the 20 benchmark subjects. Every piece has:

- `<id>.png` — the true-size canvas
- `<id>@view.png` — a nearest-neighbor upscale for viewing
- `scripts/<id>.py` — the script that draws it, rerunnable from any directory

`contact-sheet.png` is the whole set in one grid (`scripts/make_contact_sheet.py`).

## Caveats — read before drawing conclusions

- **`astronaut` is missing.** The run was executed by six parallel subagents and
  five of them were cut off by a session usage limit partway through. Most work
  survived because the scripts save incrementally, but the astronaut script was
  never written.
- **Not a controlled comparison.** Every piece here used the full craft toolset;
  there is no `baseline` arm. The protocol in `../../BENCHMARKS.md` describes the
  controlled version. Treat this run as a qualitative smoke test.
- **Mixed authorship.** Most pieces were drawn by Claude Sonnet subagents;
  `barrel` was drawn by Claude Haiku 4.5 as a check that a small model can drive
  the toolchain. The per-piece author is not otherwise recorded.
- **The PNGs are the scripts' output, not the agents' live canvases.** Agents
  iterated interactively and then saved a script. Re-running the scripts
  regenerates the art deterministically, and for a few pieces the result differs
  slightly from what the agent last had on screen. The scripts are the source of
  truth here.
- **Self-reported quality.** Each agent judged its own work against the
  subject's must-haves. Those claims have not been independently scored against
  the rubric.

## Reproducing

```bash
uv run --no-sync python benchmarks/runs/2026-07-30-stress/scripts/knight.py
```

Every script is deterministic and rewrites its own canvas, so the whole run can
be regenerated by executing all of `scripts/*.py`.
